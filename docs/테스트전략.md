# 테스트 전략

> 개정: v.17 / 2026-09-28 — Sprint 2~4 절을 `dev`(PR #331 머지 시점, 커밋 `db06359`) 의 실제 테스트 코드로 채웠다. Sprint 1 절은 원문 그대로 두고 표기만 맞췄다.
> 
> 
> **기준.** 자동화 테스트는 서비스별 Gradle 테스트(`./gradlew :<service>:test`)이며, PR 마다 GitHub Actions CI 가 `./gradlew build`(백엔드 전 모듈 테스트 포함) 와 프론트 `npm run lint` · `npm run build` 를 돌린다. 아래 "상태·Evidence" 의 날짜는 **그 테스트를 담은 PR 이 CI 를 통과하고 dev 에 머지된 날**이다. 수동 시연은 담당자가 로컬 또는 운영(`expohub.duckdns.org`)에서 직접 클릭해 확인했다.
> 
> **수준 정의.** Unit = 엔티티·순수 로직(DB·Spring 없음) / Component = 서비스 한 개 + 테스트 DB, 다른 서비스는 Mock / Integration = 실제 HTTP 계층(MockMvc)·동시성·DB 제약 포함, 다른 서비스는 Mock / E2E = 여러 서비스를 실제로 띄워 흐름 전체.
>

### Sprint Demo 시나리오·Evidence

#### 정상 흐름

- **Actor와 시작 상태**: 방문자(비로그인) → 회원가입 → 로그인. 별도로 전체관리자(SUPER_ADMIN, 시딩 계정)가 주최자 계정 발급.
- **연결할 Story**: #11, #6, #9, #10
- **사용자 행동과 확인할 결과**:
    1. 회원가입 → 201, USER Role 부여
    2. 로그인 → 200, Access Token 발급
    3. (관리자) 주최자 계정 발급 → 201, ORGANIZER Role 부여
    4. (주최자) 로그인 → 채널 생성 → 201
    5. 박람회 등록 → 201, HIDDEN 상태
    6. 회차 등록 → 201, 정원·잔여 정상 표시
    7. 공개 버튼 클릭 → 상태 PUBLISHED로 전환
    8. (방문자, 비로그인) 목록 조회 → 방금 공개한 박람회 노출, 카테고리 필터 정상
    9. 상세 조회 → 회차 시작·종료 시각, 정원, 잔여정원까지 병합되어 표시

- **상태**: PASS — 2026-09-04 로컬 환경에서 처음부터 끝까지 직접 시연, 중간 이탈 없음

#### 주요 실패 흐름

- **실패 입력 또는 Dependency 상태**: (1) 회차 등록 시 정원 0 입력 (2) 이미 공개된 박람회에 재공개 요청 (3) expo-service 다운 상태에서 회차 등록 시도
- **안전한 사용자 결과와 저장되지 않아야 할 데이터**:
    1. 정원 0 → 400 반환, "정원은 1명 이상이어야 합니다" 표시, 회차 미저장 (프론트에서 실제 클릭으로 확인)
    2. 재공개 → UI는 버튼 비활성화로 원천 차단, API 직접 호출 시 200(멱등)으로 안전 처리 확인 (curl/Invoke-RestMethod로 실측)
    3. expo-service 장애 → 503 반환 및 회차 미저장(fail-closed) — `RoundServiceTest`로 검증
- **복구·재시도 기준**: 정원 재입력 후 재시도 가능. expo-service 복구 후 동일 요청 재시도 시 정상 처리.

- **상태**: PASS — 3가지 실패 시나리오 전부 코드+실제 클릭/API 호출로 재현 확인
