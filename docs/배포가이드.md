# 실제 운영 구성

배포 개요: AWS EC2 단일 인스턴스(t3.small, 서울, Ubuntu) 위에서 docker compose 로 운영한다. 이미지는 GitHub Actions 가 빌드해 GHCR 에 올리고, 배포는 수동 실행(workflow_dispatch) CD 가 EC2 에 SSH 로 들어가 pull → up 한다. 외부 진입점은 web 컨테이너의 Nginx 하나이며, 서비스 간 통신은 Docker 내부 네트워크 동기 HTTP 만 쓴다.

## 1. 운영 구성

| 컨테이너 | 역할 | 포트(내부) | DB 스키마 |
| --- | --- | --- | --- |
| web | Nginx — React 정적 파일 서빙, /api 라우팅, HTTPS 종료, /internal 차단 | 80·443(외부 공개) | - |
| identity-service | 회원·인증 | 8081 | identity |
| expo-service | 채널·박람회·VIP 배너·자연어 검색 | 8082 | expo |
| reservation-service | 회차·예약·결제·캘린더 | 8083 | reservation |
| ticket-service | QR 티켓·체크인·체크인 AI 요약 | 8084 | ticket |
| recommendation-service | 태깅·추천·알림 | 8085 | recommendation |
| settlement-service | 정산 집계(자기 테이블 없음) | 8086 | - |
| mysql | MySQL 8.0(서비스별 스키마 분리) | 3306(외부 비공개) | - |
- 메모리: t3.small(2GB)에 JVM 6개라 서비스별 힙을 제한한다(기본 -Xmx200m, recommendation -Xmx160m). 스왑 4GB 를 켠다.
- 공용 모듈: common-security(JWT 검증), common-payment(PortOne), common-ai(Gemini 호출·한도·캐시·재시도). 모듈은 이미지 안에 jar 로 들어간다.

## 2. 접속 정보

| 항목 | 값 |
| --- | --- |
| 서비스 URL | [https://expohub.duckdns.org](https://expohub.duckdns.org/) |
| SSH 접속 | ssh -i fpt1-key.pem [ubuntu@expohub.duckdns.org](mailto:ubuntu@expohub.duckdns.org) |
| 접속 계정 | ubuntu |
| 배포 디렉터리 | ~/fpt1 (compose·nginx 설정·.env·media) |
| SSH 키 | fpt1-key.pem — 팀 내부로만 전달, 저장소·노션에 올리지 않는다 |
- 도메인: DuckDNS 무료 서브도메인. EC2 는 탄력적 IP 가 아니라 중지/시작하면 공인 IP 가 바뀐다. 서버 cron(@reboot, 5분 주기)이 DuckDNS 를 자동 갱신하므로 항상 IP 대신 도메인으로 접속한다.
- HTTPS: Let’s Encrypt(certbot standalone). 갱신 시 web 컨테이너를 잠깐 멈추는 hook 이 설정돼 있고 systemd 타이머가 자동 갱신한다.
- 보안 그룹 인바운드: 22·80·443 만 연다.

## 3. 환경변수 (~/fpt1/.env)

실제 값은 서버에만 둔다. 양식은 저장소 infra/deploy/prod.env.example.

| 변수 | 쓰는 곳 | 비어 있으면 |
| --- | --- | --- |
| DB_ROOT_PASSWORD | mysql·전 서비스 | 기동 실패 |
| JWT_SECRET | 전 서비스(동일 값 필수) | 로그인 401 |
| INTERNAL_TOKEN | 전 서비스 내부 호출 | 내부 호출 401 |
| SUPER_ADMIN_EMAIL / SUPER_ADMIN_PASSWORD_HASH | identity 최초 시드 | 관리자 계정 없음(해시는 작은따옴표로 감싼다) |
| APP_BASE_URL | 결제 리다이렉트 | 결제 후 복귀 실패 |
| PORTONE_STORE_ID / CHANNEL_KEY / API_SECRET / WEBHOOK_SECRET | expo·reservation 결제 | 결제 불가 |
| PAYMENT_SERVICE_PROFILES | expo·reservation 프로필 | 기본 prod,portone-live(실제 PortOne 검증). prod 만 두면 mock 결제 |
| GEMINI_API_KEY | expo(검색)·reservation(캘린더)·ticket(체크인 요약)·recommendation(태깅) | AI 기능만 빠지고 서비스는 정상 |
| GEMINI_MODEL | 위와 같음 | 기본 gemini-flash-latest. 503·429 잦으면 구체 모델명 지정 후 컨테이너만 재시작 |
| GOOGLE_CLIENT_ID | identity(구글 액세스 토큰의 aud 확인) | 구글 로그인만 전부 실패(fail-closed). GitHub Variables 의 VITE_GOOGLE_CLIENT_ID 와 같은 값 |
| KAKAO_REST_API_KEY / KAKAO_CLIENT_SECRET | identity(카카오 인가 코드 → 토큰 교환) | 카카오 로그인만 실패. 시크릿은 카카오 콘솔에서 켜져 있을 때만 필요 |
| NAVER_CLIENT_ID / NAVER_CLIENT_SECRET | identity(네이버 인가 코드 → 토큰 교환) | 네이버 로그인만 실패 |
| CLOUDINARY_CLOUD_NAME / CLOUDINARY_UPLOAD_PRESET | 서버에서 compose 로 web 을 직접 빌드할 때만 | CD 는 GitHub Variables 로 빌드하므로 운영에는 영향 없음 |

프론트 빌드용 값(VITE_PORTONE_*, VITE_CLOUDINARY_*, VITE_GOOGLE_CLIENT_ID, VITE_NAVER_CLIENT_ID, VITE_KAKAO_REST_KEY)은 GitHub 저장소 Variables 에 둔다. VITE_ 값은 브라우저 번들에 평문으로 박히므로 Secret 을 넣지 않는다.

## 4. CI / CD

- CI: PR 마다 백엔드 build·테스트(Testcontainers MySQL)와 프론트 lint·build 를 돌린다. 통과해야 main 에 머지한다. (개발 종료 후 dev 브랜치는 main 에 합치고 삭제했다)
- CD: 수동 실행 전용. GitHub → Actions → CD → Run workflow → 브랜치 main 선택.
    1. 서비스 6개 bootJar 빌드 → ghcr.io/likelion-backend-24th/fpt1-<서비스> 로 latest + 커밋 SHA 태그 push
    2. 프론트 이미지(fpt1-web) 빌드·push
    3. EC2 로 docker-compose.prod.yml, nginx.prod.conf, mysql init.sql 복사
    4. SSH 로 docker compose pull → up -d –no-build –remove-orphans → 오래된 이미지 정리
- main 이외 브랜치로 실행하면 빌드를 건너뛴다. 동시에 두 번 눌러도 순서대로 하나씩 돈다.
- GitHub Secrets: EC2_HOST(=expohub.duckdns.org), EC2_USER(=ubuntu), EC2_SSH_KEY.

## 5. 배포 후 확인

```
cd ~/fpt1
docker compose -f docker-compose.prod.yml ps                       # 전부 Up 인지
docker compose -f docker-compose.prod.yml logs --tail 100 <서비스>  # 기동 오류
```

- 새 Flyway 마이그레이션이 있으면 해당 서비스 로그에서 Successfully applied 를 확인한다. 실패하면 컨테이너가 재시작을 반복한다(트러블슈팅 “운영 V7 마이그레이션 실패” 참고).
- 브라우저 확인: 메인 → 박람회 목록 → 로그인 → 예약 1건 → 알림 종 → 주최자 체크인.

## 6. 자주 쓰는 운영 명령

| 목적 | 명령 |
| --- | --- |
| 서비스 하나만 재시작 | docker compose -f docker-compose.prod.yml up -d <서비스> |
| .env 변경 반영 | 위와 같음(이미지 재빌드 불필요) |
| DB 접속 | docker compose -f docker-compose.prod.yml exec mysql mysql -uroot -p |
| 정적 이미지 추가 | ~/fpt1/media/ 에 넣으면 /media/파일명 으로 서빙 |

## 7. 최초 서버 구축 (1회)

1. EC2 생성(t3.small, Ubuntu, 키페어 fpt1-key), 보안 그룹 22·80·443

3. ~/fpt1/.env 작성
4. DuckDNS 토큰 저장 + cron 등록
5. infra/deploy/https-setup.sh 실행 — 인증서 발급·자동 갱신
6. CD 1회 실행
